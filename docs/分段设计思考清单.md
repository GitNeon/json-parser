# JSON Parser 分阶段设计思考

## 阶段一：设计 JsonValue 万能数据容器（地基）

### 一、枚举类型设计思考

1. JSON 一共 6 种标准数据类型，用 `enum class JsonType` 如何定义枚举项？枚举值命名怎么规范？
2. 是否需要给枚举增加一个辅助成员函数，输入枚举名称返回字符串（方便调试打印）？

### 二、variant 存储结构核心思考（C++17 重点）

1. `std::variant` 内部需要存放哪 6 种 C++ 原生类型一一对应 JSON 类型？
2. 为什么不用 C 联合体 `union`、不用 void* 裸指针？`std::variant` 的安全性体现在哪里？
3. 嵌套结构：`std::vector<JsonValue>`、`std::unordered_map<std::string, JsonValue>` 递归嵌套会不会出现类型不完整问题？前置声明 `class JsonValue` 该怎么写？

### 三、类成员封装设计

1. 内部 variant 变量设为私有，外部完全不能直接访问，所有操作通过公有成员函数，需要设计哪些查询接口：
   - 判断类型：`is_null()`、`is_boolean()`、`is_number()`、`is_string()`、`is_array()`、`is_object()`
   - 取值转换：`as_bool()`、`as_double()`、`as_int()`、`as_string()`
   - 容器操作：数组长度、对象key数量、按下标取数组元素、按key取对象元素
2. 常量重载：为什么很多接口要写两个版本 `xxx()` / `xxx() const`？
3. 容器修改接口：给数组追加元素、给对象插入/覆盖键值对、删除节点、清空内容如何设计？

### 四、拷贝与移动语义（避坑重点）

1. JsonValue 包含大量 STL 容器，默认拷贝构造是浅拷贝还是深拷贝？嵌套结构下默认行为会不会出问题？
2. 是否需要手动实现拷贝构造、拷贝赋值、移动构造、移动赋值、析构？
3. 重载 `operator[]`：数组下标 `val[0]`、对象键取值 `val["name"]` 如何区分两种场景？越界/不存在key时如何处理（抛异常/返回空值）？

### 五、本阶段验收自测问题

- 能否手动代码构造一个嵌套结构：`{"arr":[1,true,null],"msg":"hello"}`
- 能否链式取出内层数据、修改某个数值、删除某个key

## 阶段二：Lexer 词法分析器 & Token 设计

### 一、Token 结构体思考

1. 用 `enum class TokenType` 划分所有记号类型：符号类（大括号、方括号、冒号、逗号）、字面量（字符串、数字）、关键字（true/false/null）、文件结束EOF，一共多少种？
2. Token 结构体需要哪些成员：记号类型、字符串原始值、所在行号（报错用）？
3. 是否需要重载 Token 的打印函数，调试时直观看到当前读到什么token？

### 二、Lexer 类内部状态设计

1. Lexer 需要持有原始输入字符串、当前字符索引位置、当前行数，为什么要记录行数？
2. 核心入口函数 `Token next_token()` 整体逻辑框架是什么？
3. 空白字符处理：空格、回车、换行、Tab 全部跳过，用 `<cctype>` 哪个函数判断空白？

### 三、分支状态机拆解思考

逐个场景独立思考处理逻辑：

1. 读到 `{ } [ ] : ,` 单个符号：直接生成对应Token，指针后移一位
2. 读到双引号 `"`：进入字符串解析状态机，循环读取直到闭合双引号，中间处理转义字符 `\" \\ \n \t \r`
3. 读到 `-` 或数字 `0-9`：进入数字解析，处理整数、小数点、负号（可选科学计数法）
4. 读到字母：判断是不是 `true` / `false` / `null` 完整关键字，多匹配一个字符不满足则判定非法字符
5. 读到其他无法识别的字符：直接抛解析异常

### 四、异常边界思考

1. 字符串读到末尾都没有闭合双引号怎么报错？
2. 字符串内部非法转义字符（比如 `\z`）如何判定？
3. 数字多个小数点、前导多余0（如 `0123`）属于非法JSON，是否拦截报错？

### 五、自测验收

随便一段JSON文本，调用循环 `next_token()` 直到EOF，打印所有token序列，顺序、类型、值完全正确。

## 阶段三：递归下降 Parser 语法解析器（核心难点）

### 一、Parser 类依赖与工具方法设计

1. Parser 内部组合一个 Lexer 对象，提前预读取一个当前 Token（lookahead），为什么需要预读token？
2. 必须封装三个底层工具函数，思考各自作用：
   - `Token peek()`：只偷看当前token，不消耗
   - `Token consume()`：吃掉当前token，取下一个
   - `void match(TokenType expect)`：校验当前token是不是期望类型，不对直接抛异常，对就consume掉

### 二、递归函数拆分（严格对照BNF）

```
value   ::= object | array | string | number | true | false | null
object  ::= '{' pair (',' pair)* '}'
pair    ::= string ':' value
array   ::= '[' value (',' value)* ']'
```

对应拆分成5个私有递归函数，思考每个函数的进出逻辑：

1. `JsonValue parse_value()` 总入口：根据peek到的token类型，路由到对应子解析函数
2. `JsonValue parse_object()`：匹配左大括号，循环解析key:value键值对，匹配逗号分隔，最后匹配右大括号
3. `JsonValue parse_array()`：匹配左中括号，循环解析value元素，逗号分隔，最后匹配右中括号
4. `JsonValue parse_string()` / `parse_number()` / `parse_literal()` 解析基础字面量并包装成JsonValue

### 三、语法错误校验场景思考（大量边界）

1. Object 的 key 不是字符串（比如数字当key），JSON语法非法，必须报错
2. 键值对缺少冒号、数组/对象最后多一个尾随逗号
3. 括号不匹配（开 `{` 没有闭 `}`）
4. 顶层根节点既可以是对象 `{}` 也可以是数组 `[]`，入口函数要兼容两种情况

### 四、递归风险思考

1. 极端深度嵌套JSON会不会栈溢出？要不要加递归深度上限保护？
2. 递归过程中构造JsonValue对象全部用返回值移动语义，如何避免大容器拷贝开销？

### 自测验收

输入合法JSON字符串，调用`parse()`直接生成完整JsonValue树形结构；输入畸形JSON精准抛出带行号的语法错误。

## 阶段四：Serializer 序列化模块（反向导出JSON字符串）

### 一、核心技术点思考

1. 如何遍历 `std::variant` 六种类型？`std::visit` 多态访问器怎么写重载分支？
2. 递归遍历逻辑：解析是递归建树，序列化就是递归遍历树，数组循环遍历每个子元素、对象循环遍历每一组KV

### 二、字符串拼接性能方案

1. 优先用 `std::ostringstream` 流式拼接，为什么不反复 `std::string +=`？
2. 设计两个对外接口：
   - `std::string dump()`：无缩进紧凑压缩输出
   - `std::string dump_pretty(int indent_step)`：带层级缩进格式化输出，递归每深入一层缩进累加

### 三、字符串转义反向处理

1. JsonValue里的普通字符串，输出时需要自动转义哪些字符？
2. 双引号必须加反斜杠，换行、制表符、反斜杠本身都要做转义替换

### 四、不同类型输出规则

- null → `"null"`
- bool → `"true"` / `"false"`
- number → 直接浮点转字符串（避免多余小数点）
- array 用 `[]` 包裹逗号分隔
- object 用 `{}` 包裹 `key:value`

### 闭环自测

JSON字符串 → Parser解析成JsonValue → Serializer dump出新字符串 → 再丢给Parser二次解析，两次数据结构完全一致（回环测试）。

## 阶段五：全局异常体系 + 鲁棒性加固

### 一、自定义异常类设计

1. 新建 `JsonParseError` 继承 `std::exception`，需要存储：错误行号、错误描述信息、错误位置
2. 重写 `const char* what() const noexcept` 虚函数返回异常详情
3. 在Lexer字符非法、字符串未闭合、Parser语法不匹配、取值类型错误全部统一抛出该异常

### 二、全量边界case梳理（逐条自测）

1. 空结构：`{}`、`[]`
2. 纯基础类型顶层：`123`、`true`、`"test"`（JSON合法顶层）
3. 多层无限嵌套对象、多维数组
4. 超长字符串、包含大量转义符号的字符串
5. 数字负数、小数、零值

### 三、工程内存安全配置（CMake层面）

1. 开启 ASAN + UBSAN 检测：内存越界、野指针、递归栈溢出、未定义行为
2. 编译器告警升级：GCC/Clang `-Werror`，MSVC `/WX`，所有警告强制修复
