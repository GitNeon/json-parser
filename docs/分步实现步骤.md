# C++ 手写JSON解析器分步落地指南

整体大流程：**定义数据模型（JSON Value 万能容器）→ 词法分析器 Lexer → 语法解析器 Parser（递归下降）→ 序列化输出 → 异常报错体系 → 单元测试兜底**

## 第一步：前置顶层设计（最优先做，地基）

### 目标

抽象 JSON 6种数据类型，用一个统一类 `JsonValue` 承载所有节点，这是整个解析器的核心载体。

### 1. 需要理解/用到的 C++ 核心语法与标准库

1. **`std::variant`（C++17 核心）**
    - 作用：安全的类型联合体，存放 `null/bool/number/string/array/object` 六种不同类型数据，替代老旧不安全的 C 语言 `union`
    - 配套语法：`std::holds_alternative` 判断当前类型、`std::get` 取值、`std::visit` 多分支访问（遍历不同类型做序列化、取值）
2. **容器类**
    - `double` 存储数字（JSON Number）
    - `std::string` 存储JSON字符串（处理转义字符）
    - `std::vector<JsonValue>` 对应 JSON Array 数组
    - `std::unordered_map<std::string, JsonValue>` 对应 JSON Object 对象键值对
3. **枚举 enum / enum class**
    定义 `JsonType` 枚举：`Null, Bool, Number, String, Array, Object`，对外暴露类型查询接口，方便上层判断节点类型
4. **面向对象基础语法**
    - 类的封装：私有成员存储 variant，公有成员提供 `is_null()/is_bool()/as_int()/at()` 等安全访问方法
    - 拷贝构造、移动构造、拷贝赋值、移动赋值（深拷贝，防止嵌套容器浅拷贝内存错乱）
    - 常量成员函数 `const` 重载（区分只读访问和可修改访问）
5. **异常基础**
    自定义异常类继承 `std::exception`，后续解析报错抛出

### 2. 本阶段要完成的能力（只做模型，不做解析）

1. 可以手动构造任意 JSON 节点：比如一个对象里面套数组、数组里套数字和字符串
2. 提供类型判断接口、取值转换接口（比如把Number转int/float、获取数组下标元素、获取Object key对应的value）
3. 重载运算符（可选）：`operator[]` 方便数组下标、对象key取值
4. 内存自管理，不需要手动new/delete，全部依靠STL容器自动析构释放

## 第二步：实现词法分析器 Lexer（Tokenizer 第二优先级）

### 核心作用

把一整段JSON原始字符串，切碎成一个个独立**Token（记号）**，剥离空格、换行、Tab等无关空白字符，识别合法符号，发现非法字符直接报错。

### 1. 用到的C++语法 & 标准库

1. **字符串遍历**
    `std::string` 迭代器、下标遍历、`size()`、`substr()`、`front()`、`pop_front()` 模拟字符指针前移
2. **状态机思想（手写简易有限状态机）**
    纯逻辑分支判断，区分：符号（`{ } [ ] : ,`）、数字、字符串、关键字（`true/false/null`）
3. **enum class TokenType**
    定义所有记号类型：大括号、冒号、逗号、字符串字面量、数字字面量、布尔、空值、EOF结束符
4. **封装 Lexer 类**
    私有成员：原始输入字符串、当前读取位置、当前行号（报错用）
    核心成员函数：`next_token()` 每次读取返回一个Token对象
5. **字符判断工具**
    `<cctype>` 头文件：`isspace()` 判断空白、`isdigit()` 判断数字、`isalpha()` 判断字母
6. **错误处理**
    读取到无法识别的字符、字符串未闭合、转义字符非法时，抛出自定义异常，附带**行号+错误字符**

### 2. Lexer 必须拆分出的所有Token类别

1. 单字符符号：`{` `}` `[` `]` `:` `,`
2. 字面量：STRING（双引号包裹）、NUMBER（正负、小数、科学计数可选）
3. 关键字：`true`、`false`、`null`
4. 结束标记 EOF

### 3. 本阶段验收标准

输入一段JSON文本，Lexer可以逐个吐出Token流，比如输入 `{"a":123}` 依次输出：
`LBRACE → STRING("a") → COLON → NUMBER(123) → RBRACE → EOF`

## 第三步：递归下降语法解析器 Parser（核心逻辑，第三步）

### 核心作用

吃掉 Lexer 输出的 Token 流，按照 JSON 语法规则递归构建 `JsonValue` 树形对象，是整个项目最难、最核心的模块。

### 1. 用到的C++语法与知识点

1. **递归函数（重中之重）**
    JSON本身是递归结构（对象里面可以嵌套对象/数组，数组嵌套数组），递归下降是最直观的实现方案：
    - `parse_value()`：入口总函数，根据当前Token类型分发到不同解析子函数
    - `parse_object()`：解析 `{ key: value, ... }`
    - `parse_array()`：解析 `[v1, v2, ...]`
    - `parse_string()` / `parse_number()` / `parse_literal()` 解析基础字面量
2. **Parser 类封装**
    持有Lexer实例，缓存当前预读Token，提供 `peek()` 偷看下一个Token、`consume()` 消耗当前Token、`match(TokenType)` 校验并消耗记号的工具方法
3. **循环+分支控制流**
    对象内部循环解析多个键值对、数组内部循环解析多个元素，逗号分隔符校验
4. **异常抛插**
    语法不匹配时报错：比如对象key不是字符串、缺少冒号、多余逗号、括号不匹配等

### 2. JSON官方语法规则（照着规则写递归分支）

极简BNF规则（直接对应函数拆分）

```
value   ::= object | array | string | number | true | false | null
object  ::= '{' pair (',' pair)* '}'
pair    ::= string ':' value
array   ::= '[' value (',' value)* ']'
```

### 3. 本阶段验收

输入合法JSON字符串，调用`parser.parse()`直接返回一个完整构造好的`JsonValue`对象，可以用第一步写的取值接口拿到任意嵌套数据。

## 第四步：反向功能——序列化 Serializer（第四步）

### 作用

把内存中已经构造完成的 `JsonValue` 树形结构，反向输出为标准JSON字符串，提供两种模式：压缩单行模式 / 带缩进格式化美观模式。

### 1. 用到的C++语法与库

1. **`std::visit` 遍历 `std::variant`**
    对JsonValue内部6种不同类型分别做字符串拼接输出，是variant最核心的使用场景
2. **递归遍历**
    解析是递归构建树，序列化就是递归遍历树：遍历数组每个元素、遍历对象每一组键值对
3. **字符串流 `std::ostringstream`**
    `<sstream>` 头文件，高效拼接长字符串，替代频繁 `std::string` 加号拼接
4. **字符串转义处理**
    手动处理JSON字符串转义：双引号 `"`、反斜杠 `\`、换行 `\n`、制表符 `\t` 等，还原合法JSON输出格式
5. **引用传递 `&`**
    递归传参全部使用const引用，避免大容器拷贝损耗性能

### 2. 可设计的两个对外接口

1. `dump()`：紧凑无换行压缩JSON
2. `dump_with_indent(int level)`：递归增加缩进，格式化输出

## 第五步：完善基础设施（第五步，工程健壮性）

### 模块A：全局统一异常体系

1. 自定义 `JsonParseError` 继承 `std::exception`
2. 存储成员：错误行号、错误描述、错误位置
3. 重写 `what()` 虚函数返回报错信息
4. 在Lexer、Parser所有非法场景抛出，上层main函数try-catch捕获打印

### 模块B：边界容错与鲁棒性加固

需要考虑的场景，全部加判断分支：

- 空对象 `{}`、空数组 `[]`
- 数字负数、小数
- 字符串内部各类转义字符
- 顶层直接是数组（JSON合法根节点可以是Array）
- 末尾多余逗号（非法，需要报错）

### 模块C：内存安全校验（工程化）

CMake开启ASAN/UBSan，利用工具检测递归深度过大栈溢出、容器内存越界、悬空引用等隐性bug，不用自己写内存检测逻辑。
